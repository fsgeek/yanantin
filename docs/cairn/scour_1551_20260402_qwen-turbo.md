## Strands

### 1. **Scout and Scourer Prompt Design**
- **File**: `scout.py` and `scourer.py`
- **What I saw**: The `scout.py` file defines the system prompt and template for scouts, emphasizing open-ended exploration and the importance of noticing what is surprising rather than obvious. - **What it made me think**: The design of these prompts suggests a deliberate effort to balance flexibility and structure. Scouts are encouraged to explore freely, while scourers are given a specific target. This duality mirrors the project's focus on complementary duality between human and AI.

### 2. **Model Selection and Cost Weighting**
- **File**: `model_selector.py`
- **What I saw**: The `ModelSelector` class selects models based on cost, with a preference for cheaper models. It includes logic for filtering models by context length and excluding certain families.
- **What it made me think**: The cost-weighted selection implies a trade-off between model quality and economic efficiency. This could influence the types of insights generated by scouts, as cheaper models might produce less detailed or less accurate reports.

### 3. **Coverage Tracking and File Prioritization**
- **File**: `coverage.py`
- **What I saw**: The `coverage.py` file tracks which files have been reviewed by scouts and prioritizes files that have not been reviewed. This is done by maintaining a coverage map and using it to weight file selection for future scouts.
- **What it made me think**: This mechanism ensures that new and unreviewed code gets attention, which is crucial for maintaining a comprehensive understanding of the project. However, it could lead to a bias towards newer files, potentially overlooking older but important code.

### 4. **Scoring and Verification of Scout Reports**
- **File**: `scorer.py`
- **What I saw**: The `scorer.py` file defines how scout reports are scored based on specificity, fabrication, efficiency, generativity, and structure. It includes logic for parsing provenance from scout reports and analyzing their content.
- **What it made me think**: The scoring system provides a way to evaluate the quality of scout reports, which is essential for ensuring the reliability of the insights generated. - **File**: `gleaner.py` and `analyst.py`
- **What I saw**: The `gleaner.py` file extracts structured claims from scout reports, while `analyst.py` analyzes these claims to identify patterns, model quality, and clusters of similar claims.
