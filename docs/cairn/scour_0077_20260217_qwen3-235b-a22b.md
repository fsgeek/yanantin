### Strands

#### 1. **Structural Governance via Codebase Audits**
- **What I saw**: `audit.py` systematically surveys filesystem structure (Apacheta layers, tests, Cairn tensors) and generates machine-readable reports.
- **Connections**: The `CodebaseReport` model feeds directly into the succession protocol and blueprint validation.
- **Assumptions**:
  - Fixed directory structure (`src/yanantin/apacheta`, `docs/cairn`, etc.)
  - File naming conventions (e.g., `T*.md` for tensors)
  - Test files use `def test_` patterns
- **Break impact**: Renaming directories or changing file formats would break audit data collection.

#### 2. **Fragile Blueprint Parsing**
- **What I saw**: `succession.py` uses regex to extract claims from `blueprint.md` (e.g., `**N test functions**`, `N tensors`).
- **Concern**: A single formatting change in the blueprint (e.g., adding a space in `**N test function**`) would invalidate claims extraction.
- **Missing**: Schema validation for blueprint structure. Current approach relies on "breakage as signal" but lacks resilience.

#### 3. **Orphan Detection and Tensor Graph Integrity**
- **What I saw**: `check_orphan_tensors()` uses `awaq.weaver` to ensure tensors (except T0) declare composition relationships.
- **Connection to Awaq**: This module directly depends on Awaq's tensor discovery and composition parsing capabilities.
- **Break scenario**: If tensor declaration syntax changes (e.g., `<!-- Composition: T1 composes_with T2 -->`), orphan detection would fail.

#### 4. **Entry Point Simplicity vs. Implicit Knowledge**
- **What I saw**: `__main__.py` handles CLI flags but assumes project root is 3 levels up from `__file__`.
- **Risk**: This hardcoded path logic could fail in non-standard deployments.
- **Missing**: Configurable path overrides or validation that the detected root contains expected directories.
