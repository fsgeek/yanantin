### **Preamble**  
This codebase, named *Pichay* (Quechua for "to sweep, to clean"), is a **context optimization framework for agentic LLM workflows**, specifically designed to manage and reduce bloat in long-running conversations—particularly those involving tool use, dynamic system prompts, and stateful context accumulation. It operates as a **gateway proxy** that intercepts and transforms LLM API requests/responses, applying policies to compress redundant or low-value content (especially tool results) before they reach the model.

The core insight is that in agentive workflows—like Claude Code—context grows unbounded, dominated by repeated, duplicated, or stale tool outputs and static system instructions. Pichay introduces **context paging**: evicting, summarizing, or deduplicating blocks of content when context size crosses thresholds, mimicking virtual memory management in operating systems. It logs telemetry, supports offline replay, and enables experimental comparison of different compaction strategies.

My first impression: this is a **deeply operationalized research artifact**. It’s not just a library; it’s an evaluation infrastructure for studying context economics. The project is **empirically grounded**, with configuration driven by corpus analysis (e.g., “96.3% of attention cost comes from sessions >80K avg”). It treats LLM context as a **scarce resource** to be managed—measured in bytes, tokens, attention cost, and API dollars.

This is highly relevant to **Yanantin**, which seeks a complementary duality between human and AI. Pichay embodies a *machine-side* intelligence that manages cognitive load—something Yanantin might integrate, mirror, or respond to on the human side.

### **Strands**

#### **1. Context as a Finite Resource: Economic Modeling of Attention**
- **What it does**: Pichay treats context like memory in a computer. It tracks growth, defines policy zones (normal → advisory → involuntary → aggressive), and uses thresholds to trigger actions. This is formalized in `config.py`’s `PagingPolicy`, which defines behavioral shifts at increasing token levels.
- **Yanantin relevance**: Yanantin could adopt a **dual economy**—one for the AI (context tokens, cache, attention cost) and one for the human (cognitive load, time, decision fatigue). Pichay’s telemetry (`telemetry.py`) shows how to **instrument** such an economy. Yanantin might mirror this by tracking human-side "attention tokens" or "intent stability."
- **Pattern to learn**: **Progressive engagement**—escalating intervention based on load. Human-AI duality could use similar stages: cooperative suggestion → autonomous action → override.
- **Problem solved**: Unbounded context growth. Yanantin likely faces the same: long sessions with repeated or irrelevant context.
- **Overlap**: Both projects are concerned with **efficiency of shared cognition**. Pichay optimizes for the AI; Yanantin could optimize for the pair.

#### **2. Content-Aware Compaction: Semantic Intelligence in Compression**
- **What it does**: Pichay doesn’t just trim; it **understands content**. `eval.py` breaks down system prompts into semantic components. `analyzer.py` tracks static vs dynamic content, detects duplicates, and infers tool overhead. `trimmer.py` (implied) removes duplicate blocks. `pager.py` (referenced) evicts old tool results.
- **Yanantin relevance**: This shows how **semantic analysis** can guide compression. Yanantin could apply similar logic to **human input**—detecting repeated concerns, summarizing evolving intent, or identifying when a human is "reloading" context that was already processed.
- **Pattern to learn**: **Content hashing and tracking**. `blocks.py` uses SHA-256 to assign stable IDs to message blocks, enabling reference and restoration. Yanantin could label human intents or queries, allowing the AI to say, “You asked about X before—should I reuse that context?”
- **Problem solved**: Blind trimming removes value. Pichay avoids this by distinguishing protected, pinned, or high-salience content (via `phantom_stage` and `pichay_phantom_protected`).
- **Divergence**: Pichay assumes the AI is the sole consumer of context. Yanantin must consider **dual consumers**—AI *and* human—each with different salience models.

#### **3. Proxy Architecture: Interposition as a Control Plane**
- **What it does**: Pichay is a **gateway proxy** (via `proxy.py`, `gateway.py`) that sits between the client (e.g., Claude Code CLI) and the LLM provider (Anthropic, OpenAI). It normalizes requests into a `CanonicalRequest`, applies policies, then denormalizes before upstreaming.
- **Yanantin relevance**: This is a **clean separation** of concerns: the proxy handles optimization, while the client and model remain unaware. Yanantin could use a similar **interposition layer** to mediate between human and AI—enforcing reflection, summarization, or consent checks.
- **Pattern to learn**: **Canonical model + policy pipeline**. The `core/policy.py` pipeline applies stages (phantom → paging → trim) and resolves conflicts. Yanantin could have a policy stack for **intent validation**, **bias checking**, or **tone alignment**.
- **Problem solved**: Modifying behavior without changing client or model code. This is crucial for **retrofitting duality** into existing systems.

#### **4. Observability and Experimentation: Measuring What Matters**
- **What it does**: Pichay is built for **experimentation**. `eval.py` computes metrics like n² cost, fault rate, and compaction savings. `replay.py` enables offline "what-if" analysis. `telemetry.py` logs structured events and exposes Prometheus metrics.
- **Yanantin relevance**: To establish duality, Yanantin must **measure complementarity**. Pichay’s evaluation framework shows how to define success: not just accuracy, but **efficiency, cost, sustainability**.
- **Pattern to learn**: **Structured logging + replay**. By logging `messages_full`, Pichay enables reconstruction. Yanantin could log **intent graphs**, **decision provenance**, or **consent trails** for audit and learning.
- **Problem solved**: Hard to optimize what you can’t measure. Pichay makes context economics **visible and quantifiable**.

#### **5. Human-AI Interface: The Missing Half**
- **What it does**: Pichay is **AI-centric**. It optimizes for the model’s context window. Human interaction is indirect—via logs, prompts, and artifacts.
- **Yanantin relevance**: This is the **mirror image**. Yanantin should focus on the **human side** of the duality: how to present evictions, explain summaries, or request confirmation before compaction.
- **Pattern to learn**: Pichay’s **labeling** (`blocks.py`) injects `[tensor:xxxx]` markers into messages. Yanantin could inject **intent anchors** or **duality signals**—e.g., “I’m summarizing your last three questions because they’re related.”
- **Divergence**: Pichay assumes autonomy. Yanantin may require **collaborative control**—e.g., “I’m about to page out this tool result. Is it still important?”
