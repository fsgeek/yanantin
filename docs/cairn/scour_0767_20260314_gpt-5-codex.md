### Preamble
Pointed at `src/yanantin/activity/`. First draw: the clear abstraction boundary in `store.py` and `models.py`, which everything else implements. Wanted to see how fact immutability, timestamp policy, and anchor lifecycle are enforced end-to-end.

### Strands

#### Strand α — Contract & Models (`models.py`, `store.py`)
- Observed Pydantic models built to enforce UTC-aware timestamps via `_ensure_utc` (FactRecord/MemoryAnchor validators) and frozen configs. This guarantees sortability in every backend that relies on lexicographic ISO strings (critical for DuckDB/Arango).  
- ActivityStreamStore ABC mirrors Apacheta’s immutability guarantees, exposing only append + query primitives. The contract expects backend-level enforcement of duplicate guards and temporal indexes.  
- Thought: The combo of frozen models plus validators keeps downstream code honest (no silent mutation). If this contract loosened (e.g., allowing naive datetimes), DuckDB’s string timestamp ordering and Arango’s persistent index semantics would break.

#### Strand β — In-Memory Backend (`backends/memory.py`)
- Dict + bisect pattern, guarded by `threading.RLock`; stores deep copies on read/write to avoid aliasing (matching Apacheta’s in-memory backend).  
- Temporal range queries use bisect with microsecond epsilon to include exact-bound matches. This replicates SQL “<=” semantics and ensures continuity with other backends.  
- Provider discovery is just `list(self._facts_by_provider.keys())` — order unspecified; consumers must tolerate arbitrary ordering.  
- If someone removed deep copies or locks, anchor service materialization could see mutated fact data or race conditions when multiple providers append concurrently.

#### Strand γ — DuckDB Backend (`backends/duckdb.py`)
- Schemas created once in `_init_schema`; `timestamp` stored as `VARCHAR`. Index on `(provider_id, timestamp)` matches contract expectation of O(log n) temporal queries.  
- All mutating/reading operations guarded by shared `RLock`, so connection state is serialized.  
- Query methods parameterize values (no SQL injection). Range queries compose conditions list, ensuring same semantics as memory backend.  
- Anchor storage persists raw Pydantic JSON. `_deserialize_anchor` (in truncated section) presumably reconstructs Pydantic models; would like to confirm correctness and timezone rehydration.  
- Assumption: DuckDB connection is thread-safe under external RLock. If future code tries to share connection without the lock pattern, concurrency could break.

#### Strand δ — Memory Anchor Service (`anchor.py`)
- Implements “two-flag write gate”: `update_cursor` sets `_updated`, `get_handle` sets `_referenced`, `flush` persists when both flags true. Prevents writing dormant/unreferenced anchors.  
- After flush, new handle + timestamp; `_cursors` remain (capturing latest provider positions). This means future anchor reuses same cursor state unless providers advance.  
- `materialize` performs late binding via `store.list_providers()` — ensures new providers show up retroactively. Query to `query_latest` with `before` ensures view respects anchor time.  
- `freeze` constructs summarizing strands and stores via Apacheta interface (external dependency). Anchors become provenance-rich tensors.  
- Noted no internal locking; service assumes single-threaded orchestration. If used concurrently, race conditions around flags and cursor map are possible.

#### Strand ε — Arango Backend (`backends/arango.py`)
- Uses `StorageObfuscator` to map collection/field names (privacy boundary). Ensures indexes on provider/timestamp and timestamp alone.  
- Immuntability enforced through `_key` check before insert. Timestamps converted to ISO UTC strings, mirroring DuckDB contract.  
- Error handling in `_connect_database` fail-stops with contextual message (admin provisioning required).  
- Did not view truncated AQL query-range/list/count sections, but pattern likely parallels DuckDB. Want to ensure the obfuscator is applied symmetrically on reads.

#### Strand ζ — Package Surface (`activity/__init__.py`, `backends/__init__.py`)
- Package exports only memory backend by default to avoid heavy deps; DuckDB/Arango require explicit import (documented in module docstring).  
- Activity layer exposes `MemoryAnchorService`, models, and abstract store; keeps Apacheta dependency minimal and localized (only anchor freeze uses `ApachetaInterface`).  
- This selective exposure reinforces layered architecture: in-memory for tests, heavier backends opt-in.
