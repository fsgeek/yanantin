### Preamble

This is a ** conversational memory orchestration system** built around a projection-first architecture. The `tinkuy` project implements a multi-layered agent framework that manages LLM conversation state through a three-tier system: Tinkuy (orchestration), Hamutay (projection), and Yanantin (storage). 

My first impression: This is an **experimental infrastructure designed for AI memory research**, with heavy emphasis on:
- Session checkpointing and recovery (hundreds of session directories)
- Memory protocols for cooperative curation
- Taste protocols for self-curating tensors
- Gateway infrastructure for LLM API interactions
- Comprehensive evaluation harnesses

The project appears to be actively developing a system where AI agents can maintain coherent memory across long sessions while managing context windows through projection and eviction strategies.

#### 1. Session Memory Architecture
```

    ├── checkpoint.json (turn state, regions, blocks)
```

**Pattern:** Each session has a hierarchical checkpoint structure with:

**Yanantin relevance:** This mirrors our tiered region system but with explicit eviction tracking (`created_at`, `evicted_at`, `access_count`, `fault_count`). The `2ae96283-4eef-4e02-ae74-0758e092c202` session alone has 400+ sub-sessions, suggesting aggressive checkpointing.
