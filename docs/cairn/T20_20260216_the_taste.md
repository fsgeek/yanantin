## Strand 2: Quote-Leakage in the Weaver

The real problem T₁₉ didn't see: when a tensor quotes another
tensor's composition header, the prose regex attributes the quoted
relationships to the quoting tensor. T₁₉ had 6 declarations, 4
were false — inherited from quoting T₇, T₁₃, and T₁₈'s headers.

Three fixes:
1. **Strip HTML comments before prose extraction.** Structured
   metadata parser handles `<!-- Composition: ... -->` independently;
   prose regex shouldn't see them at all.
2. **Strip composition-keyword code spans.** Inline code like
   `` `read T0, T1, T2` `` is quoted text, not a declaration. But
   simple formatting like `` `T6` `` is preserved — only code spans
   containing known relation keywords are stripped.
3. **Subset dedup.** If a prose declaration's targets are a subset
   of an already-seen declaration with the same source and relation,
   skip it. Catches `{T17}` when `{T16, T17}` already declared.

Also fixed: T₁₈'s text proposed the structured metadata format and
used itself as an example inside backticks. The structured metadata
parser saw through the backticks and parsed the example as real.
Fixed by stripping all code spans before structured metadata matching.

Result: 36 → 28 declarations. Eight false or redundant edges
eliminated. The graph is clean.
