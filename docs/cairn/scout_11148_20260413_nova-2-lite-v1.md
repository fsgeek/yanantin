### Strands

#### 1. **Privacy-as-Architecture in `EntityResolution`**
**File:** `entities.py`  
**Lines:** 10–18  

```python
class EntityResolution(ApachetaBaseModel):
    id: UUID = Field(default_factory=uuid4)
    entity_uuid: UUID
    identity_type: str
    identity_data: dict = Field(default_factory=dict)
    redacted: bool = False
    provenance: ProvenanceEnvelope = Field(default_factory=ProvenanceEnvelope)
```

**What I saw:**  
- `redacted: bool = False` is a **surgical toggle**—it doesn’t destroy data, it just hides the ability to resolve a UUID to an identity.  
- The comment says: *"Privacy-as-architecture: redacting an entity doesn't touch any tensor records. It removes the ability to resolve who the UUID refers to."*  

**What it made me think:**  
This is a **non-destructive redaction model**. It suggests the system expects **regulatory or ethical pressure** where you must forget identities without corrupting the rest of the dataset. The separation of identity resolution from tensor records implies a **modular privacy layer**—potentially useful in clinical, legal, or any high-governance context.  

**Tension:**  
If `redacted` is `False`, the `identity_data` dict may contain sensitive fields (e.g., PII). Does the system enforce encryption or redaction-at-rest elsewhere, or is this purely a logical access control?

#### 2. **Immutability as a Default in `ApachetaBaseModel`**
**File:** `base.py`  
**Lines:** 7–13  

```python
class ApachetaBaseModel(BaseModel):
    model_config = ConfigDict(
        frozen=True,
        extra="allow",
        ser_json_bytes="base64",
        validate_default=True,
    )
```

**What I saw:**  
- `frozen=True` makes models **immutable after creation**.  
- `extra="allow"` means unknown fields are accepted during parsing—this feels **conflictual** with immutability.  

**What it made me think:**  
The designers want **record integrity** (no post-creation mutation) but also **flexibility** in ingestion (accepting arbitrary fields). This could be a compromise for **backward compatibility** or **schema evolution**.  

**Tension:**  
If a record is frozen, how does the system handle **corrective updates**? Is there an explicit “replace, don’t mutate” pattern elsewhere (e.g., in `composition.py`)?
