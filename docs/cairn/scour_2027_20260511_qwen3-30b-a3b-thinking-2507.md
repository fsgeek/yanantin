## 2. The Cost-Weighted Model Selection
What I saw: `model_selector.py` uses inverse cost weighting:
```python
# Inverse cost weighting. Free models get nominal cost of $0.001/M
# to avoid infinite weight while still being heavily favored.
weights = []
for m in self.models:
    cost = m.total_cost_per_million
    if cost <= 0:
        cost = 0.001  # Nominal cost for free models
    weights.append(1.0 / cost)
```

What it made me think: This elegantly solves the cost-quality tradeoff problem. Instead of "more expensive = better", it makes cheaper models *more likely* to be selected. This is a direct implementation of the project's principle that "the cost of noticing" should inform the noticing process itself. The project isn't just observing code - it's observing *how* the code is observed.
