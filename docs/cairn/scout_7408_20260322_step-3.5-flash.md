# Chasqui Scout Report: Yanantin Project

## Preamble

Dropped into `tmp/ubuntu-vm.claude/` with a view of the Yanantin project's file system. First draw: this isn't a codebase in the traditional sense—it's a **living ecosystem**. The sheer volume of session data, agent traces, and versioned artifacts immediately signals this is a production observability platform, not a prototype. What caught my attention first was the **duality in everything**: personal vs. marketplace skills, template vs. instance, human-spawned vs. autonomous agents. The name "Yanantin" (Andean complementary duality) isn't just branding—it's baked into the architecture.

## Strands

### Strand 1: The Tensor is the Trace

**What I saw:** Every interaction leaves a permanent, addressable trace. The `projects/` directory contains hundreds of UUID-named sessions, each with:
- `subagents/` containing JSONL logs of agent reasoning
- `tool-results/` with raw outputs from file operations
- `memory/` with markdown summaries
- A root `sessions-index.json` linking everything

**What it reveals:** This system treats **epistemic observability as a first-class citizen**. Every AI thought, every tool call, every file edit is stored in a queryable format. The "tensor" metaphor becomes literal: interactions are multi-dimensional arrays of (agent, tool, input, output, timestamp, context). Look at `projects/-home-tony-projects-episode/memory/tensor_20260220_phase2.md`—they're explicitly modeling conversations as tensors.

**Tension:** The storage cost must be astronomical. Yet they keep *everything*. This suggests a philosophy: **verifiability over efficiency**. You can reconstruct any reasoning chain, but you pay for it in disk space.
