- **Thought:** This is not just output formatting. It’s a deliberate *lossy transducer* between machine-computed data and human-readable form. #### 2. **Recursive Formalism vs. Imperative Fallout**
- **Observed:** The Sierpinski algorithm is described as “recursive midpoint subdivision,” while the Mandelbrot is an imperative loop over a pixel grid. Yet both are wrapped in a CLI that treats them as *black-box generators* returning `[]string`.
- **Thought:** There’s a *duality* in the architecture: recursive elegance vs. iterative brute force, unified by a common output contract. The CLI doesn’t care which algorithm produced the lines — it just prints them. This suggests a *separation of concerns* that favors composability over algorithmic identity.
- **Lines:** `design.md` (Architecture section), `plan.md` Tasks 3 & 5.

#### 3. **Default as Dogma**
- **Observed:** Defaults are hard-coded (`--size 32`, `--depth 5`, `--iterations 100`, `--width 80`, `--height 24`). The plan doesn’t mention *configurable defaults*, only validation of inputs > 0.
- **Thought:** Defaults are *assumptions about “typical” human attention spans*. A 32-character base for a triangle assumes a terminal width; 100 iterations assume a balance between detail and patience. These defaults are not justified — they’re *cultural defaults*, like a font size in a memo. They could become a point of friction if this tool is used on a 120-column display or in a batch pipeline.
- **Lines:** `design.md` (Usage examples), `plan.md` Tasks 4 & 6.

#### 4. **Silent Gradient Expansion**

- **Thought:** This asymmetry is a *tension point*. Sierpinski users can customize *any* character; Mandelbrot users can only choose between a pre-baked palette and a single rune. Is this an oversight, or a deliberate constraint? The plan doesn’t clarify. It’s a *boundary condition* worth probing.
- **Lines:** `design.md` (mandelbrot section), `plan.md` Task 7.
