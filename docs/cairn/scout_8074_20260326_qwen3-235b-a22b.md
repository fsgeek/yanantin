### Preamble  
Observed from `src/yanantin/collector/` with focus on synthetic generators, fact recorders, and CLI structure. The deterministic seeding in synthetic filesystem data and the tension between "tensor" vs "fact stream" models drew my attention first.

---

### Strands  

#### 1. **Synthetic Data as Realism vs. Determinism**  
- **File**: `src/yanantin/collector/filesystem/synthetic.py`  
  - Uses power-law distributions for file sizes, common extensions, and directory names. The `_power_law_size` function approximates real-world filesystem patterns (small files dominate).  
  - **Thought**: The deterministic RNG seed suggests synthetic data is used for reproducible testing, but the effort to mimic realism implies it might also validate downstream analysis (e.g., anomaly detection).  
  - **Surprise**: Symlink probability (`symlink_probability`) is hardcoded at 5%, but real filesystems vary widely. Why not adapt this per environment?  

- **File**: `src/yanantin/collector/fs_events/synthetic.py`  
  - Enforces temporal consistency (e.g., no modifications before creation). Tracks `created_paths` to prevent invalid event sequences.  
  - **Thought**: This hints at a design tension: synthetic data must not only mimic *structure* but also *causal logic* to test system correctness.  

---

#### 2. **Fact Recorder Divergence**  
- **Files**: `filesystem/fact_recorder.py`, `dropbox/fact_recorder.py`, `openrouter/fact_recorder.py`  
  - All inherit `FactRecorderBase`, but strategies for `content_hash` and timestamps diverge:  
    - **Filesystem/Dropbox**: Hash entire entry via `json.dumps(sorted_keys=True)`.  
    - **OpenRouter**: Hash only `generation_id` (natural dedup key).  
  - **Thought**: The divergence suggests a lack of unified deduplication strategy. Why not standardize on a field like `generation_id` for all recorders?  
  - **Confusion**: Dropbox folders/deleted entries use `collected_at` for timestamps, which could create false "recent activity" signals. Is this a trade-off for missing metadata?  

---

#### 3. **Machine Config as a Tensor Exception**  
- **File**: `src/yanantin/collector/__main__.py`  
  - The default CLI subcommand (`_cmd_default`) directly outputs a `MachineConfig` tensor, unlike other subcommands that stream facts.  
  - **Thought**: This breaks the "everything is a fact stream" pattern. The comment says it's an exception, but why? Is machine config inherently static?  

---

#### 4. **Temporal Anchoring in Pipelines**  
- **File**: `src/yanantin/collector/pipeline.py` (via `record_and_anchor` in `__main__.py`)  
  - Anchors facts to a temporal handle (e.g., ArangoDB edge IDs), but the logic isn't visible in the code.  
  - **Surprise**: The output JSON for `_report_pipeline` includes `anchor_handle`, but how this is used for temporal queries isn’t clear.

### Open Questions  
1. **Synthetic Use Cases**: Are synthetic generators used for testing, demos, or stress-testing? The realism suggests a mix of these.  
2. **Content-Hash Strategy**: Why does OpenRouter use `generation_id` but Dropbox uses full-entry hashes? Could this lead to inconsistent deduplication?  
3. **Temporal Anchoring**: How are `anchor_handle`s used in queries? Are they for time-travel or linking facts to tensors?
