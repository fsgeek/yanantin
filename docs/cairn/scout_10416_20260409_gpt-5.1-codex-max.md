Tension: content-aware checks are now probabilistic and potentially non-deterministic; determinism and auditability are traded for flexibility.

2) **Layered validation: fast gate + deep LLM (advanced.md, “Multi-Stage Validation”)**
- Example config chains a 5s bash quick-check with a 15s prompt. The shell script whitelists trivially safe commands (`ls|pwd|echo|date|whoami`) and punts everything else to the model. This encodes a performance/coverage trade-off: minimal latency for known-safe, deferring complex reasoning to LLM. Implicit trust boundary: even “unsafe” commands are not denied by the shell, just forwarded to LLM.

3) **Contextual/conditional execution (advanced.md, “Conditional Hook Execution”)**
- Hooks check `CI` or `$USER` to skip in non-CI or for admins. The system allows user/environment-dependent policy. Assumption: local dev vs CI vs admin differ in required scrutiny. Tension: policy drift—behavior varies by environment, potentially surprising users.

4) **State sharing via temp files (advanced.md, “Hook Chaining via State”)**
- They propose writing risk level to `/tmp/hook-state-$$` and reading it in a later hook. It explicitly notes this only works for sequential events. Using `$$` (per-process) is fragile across separate invocations; no cleanup strategy shown. Assumes hooks run on the same host with shared `/tmp`.

5) **Dynamic configuration (advanced.md)**
- Hooks read `.claude-hooks-config.json` for project-specific strictness, allowed commands, forbidden paths. Assumes stable project root (`CLAUDE_PROJECT_DIR`) and jq availability. This frames hooks as policy adapters rather than hardcoded logic.
