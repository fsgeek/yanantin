# Tensor Observation: `/home/tony/projects/hamutay`

## Preamble

This codebase is **Hamutay** — a tensor projection system for managing extended AI conversations. At its core, it compresses conversation state into structured "tensors" that can be passed to subsequent conversation instances, solving the context-window limitation problem.

My first impression: this is a remarkably sophisticated system that has independently arrived at solutions remarkably similar to what Yanantin proposes. The project demonstrates deep thinking about epistemic tracking, loss declaration, and memory management — all areas where Yanantin has interests.

## Strands

### Strand 1: Tensor Projection Architecture

The system projects conversation state into structured tensors at regular intervals. Each tensor contains:
- **Strands**: Thematic units of reasoning with titles and content
- **Key Claims**: Specific claims with epistemic metadata (truth/indeterminacy/falsity)
- **Declared Losses**: Explicit tracking of what was lost in projection
- **Open Questions**: Questions that remain unresolved
- **Instructions for Next**: Guidance for subsequent cycles

This structure is remarkably similar to Yanantin's TensorRecord. The key difference: Hamutay appears to generate these tensors through LLM inference, while Yanantin stores them in a database.

**Relevance to Yanantin**: Direct architectural overlap. Hamutay's tensor schema could inform Yanantin's.

### Strand 2: Declared Losses — The Central Innovation

This is the most significant finding. In experiments like `q1_declared_losses` and `q2_declared_losses`, the system explicitly tracks what information was lost during projection:

```json
{
  "what_was_lost": "Detailed specification of conversation log format...",
  "why": "Log format unknown until inspected...",
  "category": "practical_constraint"
}
```

Categories include: `context_pressure`, `authorial_choice`, `traversal_bias`, `practical_constraint`.

The ablation results in `ablation_n20` show this matters empirically: the "no_losses" condition produces measurably different outputs than control. This validates the hypothesis that declaring losses changes model behavior.

**Relevance to Yanantin**: This is exactly what Yanantin's loss tracking should be doing. Hamutay demonstrates it works and matters.

### Strand 3: Epistemic Metadata (T/I/F)

Each key claim and strand carries epistemic metadata:

```json
"epistemic": {
  "truth": 0.92,
  "indeterminacy": 0.06,
  "falsity": 0.02
}
```

The ablation shows that zeroing these values (`no_epistemic` condition) changes model outputs. The system takes epistemic calibration seriously.

**Relevance to Yanantin**: Parallel approach to epistemic tracking. Could be a validation that Yanantin's approach is sound.

### Strand 4: Memory Management (Phantom Tools)

The `phantom.py` module implements side-channel communication between proxy and model for memory hints:

- `yuyay`: Restore evicted content
- `qunqay`: Mark content for eviction
- `memory_fault`: Request evicted content back
- `CleanupTagFilter`: Strip `<memory_cleanup>` tags from streams

This is a sophisticated memory management layer that operates below the conversation level.

**Relevance to Yanantin**: This addresses the "what happens when content is evicted?" problem. Yanantin's page fault handling could learn from this.

### Strand 5: Experiments as Epistemology

The `experiments/` directory is extensive and thoughtful:
- **ablation_n20**: 20-run ablation study testing different tensor components
- **identity_v1/v2**: Tests of identity preservation across projections
- **q1/q2_declared_losses**: Tests of loss declaration effects
- **taste/**: Human-AI collaborative reasoning experiments

The `ablation_results.json` shows quantitative analysis: dispersion, pairwise cosine similarity, generation time across conditions.

**Relevance to Yanantin**: This is how you do empirical epistemology. Yanantin should run similar ablation studies.

### Strand 6: Yanantin Integration (Apacheta Bridge)

The `apacheta_bridge.py` shows direct integration with Yanantin's storage:

```python
class ApachetaBridge:
    """Stores Hamutay tensors in Yanantin's Apacheta database."""
```

This is a working bridge between the two systems. Hamutay projects tensors; Yanantin stores them.

**Relevance to Yanantin**: The projects are already connected. This is not hypothetical.

### Strand 7: The "Pichay" Connection

Multiple tensor files reference "Pichay" — described as a demand paging system for LLM context, treating context windows as L1 cache. This appears to be a separate but related project that Hamutay builds upon.

From tensor_cycle_013:
> "Pichay operationalizes a radical reframing: LLM context windows are not memory systems — they are L1 cache."

**Relevance to Yanantin**: This is the memory hierarchy Yanantin sits on top of. Understanding Pichay helps understand the full stack.

### Strand 8: Self-Referential Validation

The system tests itself — running projections on conversations about projection. The `identity_v1` and `identity_v2` experiments test whether the tensor preserves identity across cycles.

From `identity_v2/fresh_r5/metrics.json`:
- 36,451 input tokens
- 19,582 output tokens  
- 177.1 seconds wall time

**Relevance to Yanantin**: This is the "Yanantin question" — does the artifact carry identity? Hamutay is empirically testing this.

## Closing

This is an extraordinary project. The Yanantin team should know:

1. **Hamutay is doing tensor projection** — It solves the same problem Yanantin solves (extended conversation memory) but through LLM-generated summaries rather than database storage.

2. **Declared losses is the key insight** — This is what Yanantin should adopt. Explicitly tracking what's lost is both epistemically honest and practically useful (downstream cycles can recover lost information).

3. **The projects are already integrated** — The apacheta_bridge.py shows Hamutay tensors flow into Yanantin's storage. This is not a hypothetical connection.

4. **Empirical validation exists** — The ablation studies prove that tensor components (losses, epistemic metadata, instructions, questions) affect model outputs. Yanantin should run similar experiments.

The overlap is significant. If I were advising Yanantin, I'd suggest: study Hamutay's declared losses mechanism closely — it's the most innovative part and directly applicable.
