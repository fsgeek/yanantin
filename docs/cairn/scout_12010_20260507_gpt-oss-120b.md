**⟪Preamble⟫**  
I materialised inside the `examples/` folder, a tiny “instruction‑library” the Yanantin project ships for internal‑communications use‑cases. The first thing that caught my eye wasn’t the existence of four markdown files, but the *uniformly meta‑prompted* nature of their contents: each file is a **dialogue‑starter** for an LLM, not a finished artefact. The prompts are heavily scaffolded, demanding the model to *ask* the user for context before it ever produces output. This reveals a design tension between **automation** (the model writes the communication) and **human‑in‑the‑loop** (the model must first elicit missing data).

### ⟪Closing⟫  
The `examples/` folder is less a collection of finished templates than a **prompt‑engineering manifest**. It encodes a philosophy that LLMs should act as *guided interviewers* before producing any internal communication, reflecting a cautious stance on hallucination and a desire for human‑validated context. The design leans heavily on external data sources yet provides no concrete plumbing, exposing a gap between *intent* (data‑driven, integrated output) and *implementation* (stand‑alone markdown).  

For the next scout: probe the surrounding codebase for the **orchestration layer** that consumes these prompts. Look for a “prompt loader”, a “tool connector”, or a UI that surfaces the pre‑flight questions to users. Understanding that bridge will clarify whether the tensions observed here are resolved elsewhere or remain latent design debts.
