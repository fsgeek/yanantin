# Chasqui Scout Observation Tensor
## Core Metaphor & Cohesion
The entire module leans into the Inca chasqui messenger metaphor: scouts wander freely, scourers target specific nodes, the `cairn` stores all observed tensors, and every report is framed as a structured, transparent message. This consistency makes the pipeline feel intentional rather than ad-hoc.

## Critical Duplication (Low-Hanging Refactor)
Three core utilities are reimplemented across files:
1.  **Path parsing**: Identical backtick-wrapped file path regexes exist in `scorer.py`, `coverage.py`, and `gleaner.py`
2.  **Section extraction**: Markdown section extraction logic is duplicated between `scorer.py` and `gleaner.py`
3.  **Timestamp/provenance parsing**: `coverage.py` has its own timestamp regex, while `scorer.py` parses headers via string extraction

## Solved Pain Points (And Unfixed Gaps)
The `coverage.py` docstring explicitly calls out the original failure: the project's activity stream subsystem was never reviewed by any scout, despite being a major new addition. The module fixes the uniform random sampling bias that left obscure/new code ignored, but *itself* still has an unaddressed gap: the activity stream layer it relies on for `_build_activity_map` in `coordinator.py` is the very code that was never reviewed.

## Transparency as a First-Class Citizen
Every scout/scour report and verification step requires declaring **declared losses** (what you chose not to examine) and open questions. This eliminates overclaiming and makes blind spots explicit—core to the project's epistemic observability goal.

## Automated vs. Human Work Split
The scorer module deliberately excludes semantic novelty scoring (left to human judges) and uses convergent cross-scout observations as a proxy for verified novelty. This balances automated scaling with subjective, human-led quality control.

## Modular Robustness
Most optional components fail gracefully:
- Willay integration is guarded behind optional imports
- The DuckDB activity store fallback returns `None` instead of breaking the pipeline
- File reading/parsing errors skip broken reports without crashing the coordinator

## Targeted vs. Free Exploration
A clear split between:
1.  **Scouts**: Free-roaming observers given only a vantage point
2.  **Scourers**: Targeted observers given a specific file/scope to examine
Both use the exact same structured tensor output format, making downstream parsing consistent.

## Feedback Loop
Scout prompts explicitly tell new scouts to build on prior findings (and ignore the obvious). The `prior_findings` section in the scout template shows *denied* verified claims from previous scouts, framing the new scout's job as fixing gaps and correcting past errors.
