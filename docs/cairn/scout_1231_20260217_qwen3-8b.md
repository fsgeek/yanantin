### Strands

#### Strand 1: Provenance as Infrastructure
**What I saw**  
- `docs/cairn/` contains tensors with explicit vantage markers and losses (e.g., `T10_20260209_post_compaction.md` declares "technical continuity survives, experiential does not").

**What it made me think**  
Provenance is not just metadata—it’s a **constraint**. The codebase treats it as *structural*:
- Tensors are **non-overwriting** (e.g., `T10_20260209_post_compaction.md` says "does not overwrite T₄").  
- The base model’s `frozen=True` and `extra="forbid"` make it impossible to mutate or extend records, aligning with the narrative principle that "nothing that matters is allowed to be anonymous, mutable, or silently extended."  
- The `ots` files are the **backend** for this, storing tensor records in a format that seems to support versioning (see `ots/0005f03cf1.ots`).

#### Strand 2: Tensor as Authored Loss
**What I saw**

- `docs/cairn/scout_0002_20260210_deepseek-chat-v3.1.md` and `scout_0002_20260210_granite-4.0-h-micro.md` both reference `src/yanantin/apacheta/models/tensor.py`, which includes:

**What it made me think**

- The "ballot" metaphor suggests that tensor creation is a **voting process**—a claim is made, losses are declared, and the tensor is stored as a verifiable record.  
- The term "bounded verification" implies that the project is **not** about full fidelity, but about **controlled abstraction**.

#### Strand 3: Apacheta as Interface Layer  
**What I saw**  
- `src/yanantin/apacheta/clients/gateway.py` implements `ApachetaGatewayClient`, which:
  - Uses `httpx.Client` with `X-API-Key` for authentication.  
  - Maps HTTP errors to Apacheta-specific exceptions (e.g., 409 → `ImmutabilityError`).  
  - Imports `CompositionEdge`, `CorrectionRecord`, and `SchemaEvolutionRecord` from `src/yanantin/apacheta/models/composition.py`.  

**What it made me think**  
Apacheta is **not** a monolith. It’s a **layered interface**:
- The gateway client is **decoupled** from the backend logic, which is handled by Pukara (as seen in `check_access(...)`).  
- The client enforces **schema constraints** (e.g., `CompositionEdge` and `SchemaEvolutionRecord` are model types that require strict validation.  
- The project uses **HTTP as a control plane**, not a data plane.
