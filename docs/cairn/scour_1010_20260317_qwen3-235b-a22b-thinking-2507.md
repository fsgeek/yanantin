## Strands

### 1. Temporal Integrity as Foundational Constraint
The strict enforcement of UTC timestamps permeates the entire module. In `models.py`, the `_ensure_utc()` function (lines 18-28) actively rejects naive datetimes with: "Naive datetimes are rejected — ambiguous timestamps corrupt sort order in every backend." This isn't just a preference — it's treated as a correctness requirement across all implementations. The DuckDB backend stores timestamps as VARCHAR (ISO 8601) specifically because "ISO 8601 strings sort correctly only when the timezone offset is uniform" (duckdb.py, line 26).

What this makes me think: The project treats temporal ordering as non-negotiable. This suggests the system handles scenarios where event sequence is critical to meaning — likely fundamental to the "epistemic observability" goal. Changing this to allow naive timestamps would break sort ordering across all backends, corrupting temporal queries.

### 2. The Two-Flag Write Gate Pattern
The MemoryAnchorService (anchor.py, lines 35-160) implements a sophisticated persistence strategy where:
- `update_cursor()` sets the "updated" flag when providers report new data
- `get_handle()` sets the "referenced" flag when callers request state
- `flush()` only persists when both flags are true

This pattern mirrors Indaleko's ActivityContextService (mentioned in docstrings) but with Yanantin-specific adaptations. Crucially, the handle only advances when both conditions are met (anchor.py, lines 105-108), creating a Lamport clock-like progression.

What this makes me think: This is a brilliant optimization for high-write/low-read scenarios. Providers can push updates frequently without triggering disk writes, and the system only materializes state when actually needed. It's a perfect embodiment of the "complementary duality" concept — machine-generated updates (AI) only become observable knowledge (human) when referenced.

### 3. Late Binding Resolution Strategy
The `materialize()` method (anchor.py, lines 112-138) implements what the docstring calls "late binding": when resolving an anchor, it queries *all current providers* rather than just those in the anchor's cursor list. As noted: "A new provider registered after the anchor was created will appear in the view if it has facts before the anchor's timestamp."

What this makes me think: This design creates remarkable resilience to schema evolution. New data sources can be added without invalidating historical anchors — the system remains "forward compatible" by design. This suggests the project anticipates evolving data landscapes where the set of providers isn't fixed.

### 4. Storage Backend Abstraction Quality
The clean separation between abstract interface (`store.py`) and concrete implementations (backends) demonstrates thoughtful architecture. Despite different storage paradigms:
- Memory: dict + bisect (memory.py)
- ArangoDB: document + AQL (arango.py)
- DuckDB: SQL + indexes (duckdb.py)

All implement identical temporal query patterns with O(log n) performance. The DuckDB implementation specifically calls out avoiding the "load-all-then-filter" antipattern that "at 28.5M facts... is not viable" (duckdb.py, lines 11-12).

What this makes me think: The abstraction is robust but reveals subtle tensions. The ArangoDB backend includes storage obfuscation (`StorageObfuscator`), while DuckDB explicitly states "No obfuscation needed — the trust boundary is at Pukara" (duckdb.py, lines 35-36). This suggests different security models for different deployment scenarios.

### 5. Epistemic Bridge Design
The `freeze()` method (anchor.py, lines 140-176) is where temporal data becomes epistemic knowledge. It transforms an ephemeral `AnchorView` into a permanent tensor with:
- Provenance tracking (SourceIdentifier with anchor handle)
- Structured content (two-strand representation: summary + data)
- Lineage tagging ("anchor", "frozen-view")

Crucially, the docstring identifies this as "an authored act" — highlighting the human-AI collaboration point.

What this makes me think: This is the precise location where the project's "complementary duality" becomes concrete. Machine-generated temporal streams become human-observable knowledge through this deliberate freezing operation. The strand structure (summary + data) reveals a thoughtful approach to making temporal data interpretable.
