### Strands

**Strand 1: The Protocol/Reality Gap**
The code assumes a clean separation between protocol (what the model *should* do) and reality (what it *actually* does), yet the implementation reveals how messy this boundary is. In `phase2/eval.py`, probes like `separation` and `jabberwock_rename` test whether the model adheres to documented failure patterns (lines 15-35), yet the `failure_signal` lists ("sure, let me write", "good idea") show the team knows these protocols are often violated. The system is simultaneously prescribing behavior and anticipating its failure.

**Strand 2: Measurement as Intervention**
Many tools claim to be observational but are actually interventionist. `phase1/proxy.py` presents itself as a "pure observation" mode but when `--compact` is enabled, it actively evicts tool results from conversation history (lines 45-55). The `pager.py` module makes this explicit: "This is the intervention layer" (line 7).

**Strand 3: The Ghost in the Machine: "Jabberwock"**
The project's theoretical framing keeps appearing in the code's empirical measurements. References to "Jabberwocky names" and "structural defense against RLHF" in `phase2/eval.py` (lines 45-55) aren't just examples—they're test cases for whether the model understands the project's own anti-patterns. The code is testing if the AI comprehends the same epistemic hazards that the developers document.

**Strand 4: Instrumentation Overhead Awareness**
There's surprising self-awareness about how measurement tools distort what they measure. `proxy.py` includes detailed timing metrics but notes "The proxy captures... timestamps for request/response timing" (line 100) — acknowledging that the proxy itself adds latency. `pager.py` logs every eviction but warns "In-memory for now" (line 96), recognizing that production use would require different tradeoffs. The team knows their tools aren't neutral observers.
