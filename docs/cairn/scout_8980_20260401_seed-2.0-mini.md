### Strands
#### Strand 1: Complementary Duality as Pipeline Architecture
The entire chasqui workflow embodies the yanantin concept explicitly: AI handles scalable, deterministic work, while humans step in for subjective, judgment-driven tasks. 
- AI owns the free-roaming `Scout` and targeted `Scourer` LLM agents, plus the `Gleaner` (regex-based claim extraction), `Analyst` (hard-threshold clustering), and `Scorer` (objective metric scoring). No LLM calls are used in these deterministic modules.
- Humans are required for semantic novelty judgment (explicitly excluded from automated scoring per `scorer.py`), claim verification, and ledger curation via the optional `Willay` epistemic receipt system.
- The pipeline split is baked into every module: `analyst.py` rejects subjective semantic clustering in favor of word-overlap similarity, `scourer.py` uses rigid prompt templates for targeted LLM outputs, and `attestation.py` enforces consistent epistemic humility across all verified claims.

#### Strand 2: Optional Ledger with Hidden Assumptions
The `attestation.py` module bridges Chasqui's verification results to formal Willay receipts, but it is strictly optional — all Willay imports are guarded behind a try/except block, so the system can run without a ledger. What stood out here:
- Every verification automatically includes three hardcoded common declared losses: single-model verification risk, LLM hallucination bias, and temporal code drift. This enforces epistemic humility even for confirmed claims: even cross-verified results carry 0.3 indeterminacy.
- A hidden file path assumption: `verification_to_receipt` uses `Path(file_path)` directly, which relies on the current working directory matching the project root. Relative paths will break if the tool is run from a different location.
- Missing file handling: if a claimed file is unreadable or does not exist, the evidence artifact uses an empty SHA256 hash as a fallback, which avoids pipeline failure but creates opaque behavior for downstream users.

#### Strand 3: Rigid Formatting as Reliability Backbone
Every single module in this directory produces or consumes structured tensor outputs with identical mandatory sections: Preamble, Strands, Declared Losses, Open Questions, Closing. This is not a trivial formatting choice:
- `scout.py` and `scourer.py` include explicit prompt templates forcing LLMs to follow this format.
- `gleaner.py` and `analyst.py` use regex patterns to extract these standardized sections reliably, even accounting for minor formatting variations like bold section headers.
- The `__init__.py` file even leans into this theme with a single poetic comment: *"Chasqui — the messengers. Playful, singing, and sharing with their community."*

#### Strand 4: Rejection of Subjective AI Judgment
Across the pipeline, there is a deliberate rejection of subjective AI scoring:
- `scorer.py` explicitly excludes semantic novelty scoring, noting it requires human judgment.
- `analyst.py` uses a hard threshold of 3+ distinct models to define "topological" (structurally verified) claims, avoiding any subjective call for "consensus".
- `is_verification_meta` uses rigid regex patterns to separate original observations from meta-claims about other scouts' work, eliminating subjective classification of claim types.
