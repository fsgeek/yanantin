### Preamble  
I examined the `src/yanantin/chasqui` directory, focusing on code that implements the **Yanantin project's epistemic observability** through composable tensors. The target is core infrastructure for handling model dispatch, claim analysis, and verification. The first striking pattern is the **heavy use of dataclasses** for structured data (e.g., `ModelInfo`, `ClaimGroup`, `ExtractedClaim`), which enforces clarity but may limit flexibility. The system’s **deterministic, regex-driven parsing** (e.g., in `is_garbage`, `parse_provenance`) balances simplicity and brittleness.  

---

### Strands  

#### **Strand 1: Cost-Weighted Model Selection**  
The `model_selector.py` uses inverse cost weighting to select cheaper models more often. This is clever for budget optimization but assumes cost ≈ utility, which may not hold. A $0.10/M model (e.g., `deepseek-chat-v3.1`) is 10x more likely to run than a $1.00/M model. However, free models (`total_cost_per_million <= 0`) get a $0.001 nominal cost—this avoids division-by-zero but could still skew selection toward free models disproportionately.  

**Concern**: If a high-cost model consistently produces better claims, the system would never fully leverage it. The `stats()` method tracks model pool properties but lacks historical learning to adjust weights over time.  

---

#### **Strand 2: Verification as a Metadata Layer**  
The `analyst.py` and `gleaner.py` treat verification as a **second-order observation** (meta-claims about claims). The `is_verification_meta` regex (e.g., `"Verdict"`, `"Evidence confirms"`) identifies these, but the pattern lacks context—e.g., "Verification" in a filename could be misflagged. The `ClaimCluster` groups claims by file references, but clusters lacking cross-model agreement (`is_topological: model_count < 3`) are treated as low-confidence.  

**Assumption**: Consensus across 3+ models equals truth. This works statistically but risks excluding valid minority insights.  

---

#### **Strand 3: Coverage-Driven File Selection**  
The `coverage.py` tracks file review freshness using timestamps, prioritizing stale or unreviewed files. Files never reviewed (`EPOCH_ZERO`) get maximum weight. The `_lookup_coverage` method falls back to **basename matching** (e.g., `evolve.py` matches `/src/evolve.py`) to handle partial paths—a pragmatic solution but risky if multiple files share the same basename.  

**Edge case**: A new `utils.py` in two directories would be conflated, misrepresenting coverage.  

---

#### **Strand 4: Provenance Tracing as a First-Class Concern**  
Every scout report embeds a provenance header (`<!-- Chasqui Scout Tensor ... -->`), parsed via regex in `scorer.py`. This ensures **auditability** of model choices and costs. However, the manual parsing (`parse_provenance`) risks breaking if the header format evolves.  

**Dependency**: The system assumes all models expose their cost via `pricing` fields in OpenRouter’s API—this could fail if a provider uses non-standard fields.  

---

#### **Strand 5: Epistemic Receipts as a Verification Ledger**  
The `attestation.py` converts verification results to `willay` receipts, but this dependency is **optional** (guarded imports). The declared losses (e.g., "single-LLM verification", "hallucination risk") are well-modeled but lack quantitative scoring (e.g., confidence intervals).

### Closing  
The codebase is **cohesive and logically structured**, with clear separation of concerns (model selection, claim analysis, coverage tracking). Its **strengths** are:  
- Deterministic, regex-based parsing avoids LLM dependency in critical paths.  
- Coverage-driven file selection reduces redundant reviews.  
- Provenance tracing ensures auditability of cost and model choice.  

**Weaknesses**:  
- Over-reliance on regex/strings for parsing could fail with edge cases.  
- Lack of historical feedback to refine model selection weights.  
- External dependencies (e.g., DuckDB for activity tracking) introduce single points of failure.  

To modify this code:  
1. Add **unit tests** for regex-based parsing logic.  
2. Implement **adaptive weighting** for models based on historical performance (not just cost).  
3. Replace basename coverage fallback with a **fuzzy path matching** solution.
