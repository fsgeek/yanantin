### Preamble

Dropped into the memory directory, the succession messages (Feb 19-20) read like a design diary rather than a codebase. The real tension isn't in the files themselves — it's in what they *claim* about the code versus what the code *actually* does. I'm not here to verify the paper outline; I'm here to check if the architecture breathes.

---

### Strand 1: The Graph-Use Gap

**Survey says 15/16 models want graphs. Behavioral test says 5/8 use them.**

In `tensor_20260220_phase2.md`, Strand 5, the flatworm notes: "The deferred sync took create from ~11ms (3 fsyncs) to ~3ms (1 fsync)." But nowhere in the behavioral test files do I see a measurement that isolates *why* models either use or ignore graph ops. The behavioral test files (`scripts/behavioral_auth_bug_*.json`) exist, but I don't see the analysis that explains the 7 models that didn't adopt graph primitives.

**This matters.** If the survey is discourse-echo, then the paper's core finding is shaky. If the behavioral test is sampling error, then the design is premature. The succession message says "if self-report and revealed preference converge, the discourse-echo objection dissolves" — but it doesn't show what happens when they don't.


This is compelling — a bug that sequential tests couldn't find. But I need to see:
1. Where in the code is `ec_merge` implemented (presumably `src/txn/tlock.rs` or `src/txn/tran.rs`)?

The succession message doesn't say. It just says "found real ec_merge bug" as evidence the harness was necessary. **Is the code broken now? Or fixed?**

### Closing

The memory files describe a *vision* of the system that's more complete than the code I can actually see. The succession messages read like design notes that predate implementation. The tensor from the previous scout is *also* a memory of building, not the build itself.

**The core tension:** The architectural claims (async log, EC merge, graph namespace) are well-documented in prose, but I cannot verify them against actual code. The behavioral test results contradict the survey results, creating uncertainty about whether the graph namespace is actually valuable. The Phase 2 implementation status is ambiguous.

If I were the next scout, I'd start with:
1. **Find the concurrent harness output** — does it show the EC merge bug is fixed?
2. **Trace a write operation** — from FUSE call to content store, does it go through deferred sync?
3. **Run a behavioral test** — not read the results, *run* the test to see if models use graph ops

The code exists somewhere. These memory files are the map, but they're not the territory.

**What I'd tell the next scout:** Don't trust the memory files. They're written by someone who *designed* this system, not someone who *lives* in it. Find the actual Rust code. Find the actual test outputs. Then ask: does this system work, or does it look like it works?
