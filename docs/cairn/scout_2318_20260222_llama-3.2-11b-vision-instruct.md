### Preamble
I observed the Yanantin project from the vantage of a chasqui scout, exploring the codebase and reporting on notable findings. The sheer volume of `docs/cairn/scout_*.md` files drew my attention first, indicating a systematic, automated verification effort.

### Strands
#### 1. **Self-Documenting Verification Loop**
Every `scout_*.md` file starts with a standard header that records model ID, cost, token usage, and a timestamp. The body follows a fixed schema: `Verdict`, `Evidence`, `Reasoning`, `Declared Losses`, and `Final Determination`. These reports collectively form a continuous audit of the codebase, with each model acting as an independent observer.

#### 2. **Hook-Driven Compaction**
The `.claude/hooks/precompact_tensor.py` script runs when Claude’s context is about to overflow. It reads the session JSONL, assigns a unique tensor number, and writes a “compaction tensor” to `docs/cairn/compaction/`. The hook’s docstring makes it clear that it deliberately documents the *difference* between the instance’s natural output and the automated capture, providing a calibration signal.

#### 3. **Tensor Operators**
Under `src/yanantin/apacheta/operators` lie functions `compose`, `correct`, `dissent`, `evolve`, `negate`, and `project`. They manipulate tensor objects, building an algebra over observations. Tests in `tests/unit/test_operators.py` validate that these operations produce expected provenance edges.

#### 4. **Backend Multiplicity**
The project ships three backends—`memory.py`, `duckdb.py`, and `arango.py`. Each implements the same interface to store tensors and edges. Unit tests (`test_memory_backend`, `test_duckdb_independent`, `test_arango_independent`) verify behavioral equivalence.

#### 5. **Weaver and Composition Extraction**
`src/yanantin/awaq/weaver.py` parses tensor files to extract composition declarations. The unit tests (`tests/unit/test_awaq_weaver.py`) cover normalization of tensor names (Unicode subscripts, LaTeX subscripts), extraction of tensor names from file paths (legacy naming schemes), and pattern matching for composition relationships.

#### 6. **Provenance and Signing**
The `docs/signing.md` and `src/yanantin/provenance` modules implement a per-commit signing scheme, with separate keys for human and AI commits. The `tests/red_bar/test_provenance.py` asserts that each commit’s signature is verifiable.

### Closing
The Yanantin repository is a living experiment in epistemic observability, recording what AI models see, how they reason, and how that knowledge is stored, signed, and verified. The design—multiple backends, immutable tensors, a compaction hook, and a robust test suite—suggests that the authors are building a nervous system for software.
