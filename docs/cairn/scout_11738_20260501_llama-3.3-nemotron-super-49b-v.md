### Strands  

#### 1. **LLM as a Validation Layer**  
**Observation:**  
In `advanced.md`, multi-stage validation combines command hooks (fast, deterministic checks) with prompt hooks (LLM analysis). The `quick-check.sh` script exits 0 even for unsafe commands, deferring judgment to the LLM. Similarly, `migration.md` replaces bash scripts with prompts that ask the LLM to reason about destructive operations (e.g., `rm -rf` variations).  

**Implications:**  
- **Assumption:** The LLM can reliably detect edge cases (e.g., path traversal, dangerous commands) without explicit rules.  
- **Tension:** This shifts responsibility from code to model inference, introducing variability. For example, the LLM might miss subtle patterns or overblock benign commands.  
- **Surprise:** The system trusts the LLM to handle ambiguity better than code, despite potential hallucinations or inconsistencies.  

---

#### 2. **State Management via Temp Files**  
**Observation:**  
In `advanced.md`, hooks share state via temporary files (e.g., `/tmp/hook-state-$$`). This works only for sequential hooks, not parallel ones.  

**Implications:**  
- **Assumption:** Sequential execution is sufficient for most workflows.  
- **Tension:** This approach is fragile—temp files could leak state between sessions or fail under concurrency. It’s a stopgap solution for a system lacking built-in state-passing mechanisms.  
- **Surprise:** The documentation acknowledges the limitation but offers no alternative, implying it’s an accepted trade-off.  

---

#### 3. **Migration Trade-offs**  
**Observation:**  
`migration.md` contrasts bash scripts (explicit, rigid) with prompt hooks (flexible, LLM-driven). The "after" examples remove error codes and script logic, relying on natural language responses.  

**Implications:**  
- **Assumption:** Maintainers prefer LLM maintainability over deterministic control.  
- **Tension:** Prompt hooks sacrifice transparency—denial reasons are generated by the LLM, not hardcoded. Debugging becomes harder if the model’s reasoning is opaque.  
- **Surprise:** The migration guide emphasizes ease of use but downplays risks like model bias or latency (e.g., 15-second timeouts vs. instant scripts).  

---

#### 4. **Context-Awareness Assumptions**  
**Observation:**  
In `patterns.md`, the "Test Enforcement" pattern asks the LLM to review the transcript for test execution. Similarly, "Context Loading" uses scripts to detect project types (Node.js, Rust).  

**Implications:**  
- **Assumption:** The LLM can parse transcripts accurately to infer user intent (e.g., whether tests were run).  
- **Tension:** This relies on the user explicitly mentioning tests in the conversation. If tests are run silently (e.g., in a script), the LLM might miss them.  
- **Surprise:** The system blends script-based detection (e.g., `package.json` existence) with LLM-based inference, creating a hybrid logic that could confuse users.
