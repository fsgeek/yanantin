#### **5. Confidence Scoring**
**What I saw:**
- Confidence is scored from `0.0` (low) to `1.0` (high) based on linguistic patterns:
  - Definitive language (`is`, `always`) → higher confidence.
  - Hedged language (`seems`, `might`) → lower confidence.
  - Quantitative assertions (`5 tests`) → higher confidence (verifiable).
- The default confidence is `0.5` (Line 30).

**What it made me think:**
- **Why this matters:** Confidence scores help the `Verify` step prioritize claims. For example:
  - A `confidence=0.9` claim about a file’s existence might auto-verify.
  - A `confidence=0.3` epistemic claim might trigger a human review.
- **Limitations:**
  - The scoring is *linguistic only*. For example, a claim like "The file `x.py` exists" might have high confidence, but if `x.py` doesn’t exist, the claim is false. This is a semantic gap the gleaner doesn’t address.
  - **Line 110:** `_QUANTITATIVE_PATTERN` boosts confidence for claims like "3 tests." But what if the count is wrong? The gleaner can’t verify this—it only *scores* it.
- **Connection to broader project:** This aligns with Yanantin’s goal of epistemic observability by quantifying uncertainty. However, it assumes that linguistic confidence correlates with *truth*—a risky assumption.

**What would break if this changed?**
- If confidence thresholds are adjusted (e.g., `0.7` instead of `0.5`), the `Verify` step might misclassify claims as verifiable/inverifiable.
- Adding new confidence modifiers (e.g., "expert review") would require extending the pattern matching.
