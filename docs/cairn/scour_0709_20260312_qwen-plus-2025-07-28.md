### Preamble  
I examined **15 scout reports**. At first glance, the collection felt less like a coordinated investigation and more like a murmuration of models—each reacting to its own prompt, some verifying claims with surgical precision, others offering speculative strands like tendrils into the dark. What struck me immediately was the **asymmetry in effort**: a few models (like `olmo-3-32b-think`, `gpt-4.1-nano`, `qwen3-235b-a22b-2507`) wrote long, reflective analyses with layered reasoning, while others (`deepseek-v3.2`) delivered nothing at all. The cost distribution is wild: one report cost **500x** another. Yet the cheapest models sometimes delivered sharp, correct verdicts. The most expensive didn’t always say more that mattered.

There’s a **meta-pattern**: the act of verification has become recursive. Models are now verifying not code, but *other models’ claims about code*. This creates a **second-order epistemology**—truth is no longer in the code, but in the chain of statements about it. And in that chain, contradictions emerge not from code misreading, but from **differing interpretations of what counts as evidence**.

### Strands

#### **1. Consensus on Core Code Patterns**  
Multiple models converge on key architectural truths:
- **`weaver.py` uses regex** to extract composition rules. This is confirmed independently by `qwen3-30b-a3b-instruct-2507` and referenced in a claim by `meta-llama/llama-4-maverick`. Even `z-ai/glm-4-32b` notes a prior model’s *avoidance* of regex details, indirectly affirming their existence.

The consensus is **strongest on file-level facts** that are directly observable from code comments or structure.

#### **2. Contradictions: Who’s Right?**  
Contradictions cluster around **file existence and reference**:
- `mistralai/mistral-small-24b-instruct-2501` **denied** a claim that `memory.py` is missing—correctly, because the file *was* provided and clearly exists.

In every verified case, the **denying model is correct**. The original claims being verified were often **inaccurate or misstated**. This suggests a **drift in claim fidelity**—models are making claims that are not grounded, and later models are acting as fact-checkers.

The **biggest blind spot is action**: models verify textual presence, but not **causal integrity**. Does the system *work* as claimed? Or just *look* like it does?

#### **4. Recurring Claims and Their Fate**  
- **“File X does not mention Y”** — this pattern appears 5+ times (`CLAUDE.md`, `predecessors.md`, `scout.py`). Often denied. It’s a **common failure mode**: models assume absence from silence, but silence isn’t evidence.
- **“Model Z avoided topic W”** — used as *evidence* of topic W’s existence (e.g., “didn’t delve into regex”), which is logically valid but meta.
- **“The system uses embedded provenance”** — mentioned by `gpt-4.1-nano` and echoed in spirit by others, but **no one verified the data flow** from `store_tensor()` to actual storage.

These claims are **self-reinforcing**: once a narrative (e.g., “provenance is key”) emerges, later models reflect it without checking.

#### **5. Model Artifacts vs. Genuine Findings**  
- **Cost correlates with verbosity, not accuracy**. `gpt-4.1-nano` and `olmo-3-32b-think` are expensive and thoughtful, but their open questions are **not answered by cheaper models**—they’re just ignored.

The **genuine findings**—regex in `weaver.py`, persistence in `duckdb.py`—are **not model-specific**. They’re in the code. The **artifacts** are the **overinterpretation** (e.g., recursive tautology in `predecessors.md`) and **false negatives** based on missing files.

### Closing  
The scouting system is **alive but uncoordinated**. It’s finding real things: backend types, regex usage, file references. But it’s also **drowning in second-order noise**—models verifying other models’ claims about not verifying things. The **signal-to-noise ratio is declining** as meta-claims proliferate.

**What’s working**:
- **Literal claim verification** is robust. When a file is provided, models can correctly confirm or deny.
- **Discrepancy detection** works: models catch when claims contradict evidence.

**What’s failing**:
- **Depth over breadth**: no model is building a holistic view.
- **Priority blindness**: no one is asking, “What’s most important to verify?”
- **Feedback loop**: incorrect claims (e.g., “`predecessors.md` claims to be absent”) are made and must be corrected later, wasting compute.

**Recommendations**:
1. **Introduce claim triage** — not all claims are worth verifying. Filter for high-impact ones.
2. **Require cross-file verification** — force models to check related files (e.g., if `store.py` calls `provenance.py`, provide both).
3. **Audit the auditors** — track which models make false claims vs. correct ones. Use that to weight future sampling.
4. **Runners, not just scouts** — add a role that *executes* code or checks logs, not just reads it.

The system is **not missing critical bugs yet**, but it’s **one layer of indirection away from irrelevance**. Right now, the code is still the truth. But if the scouts keep only staring at each other, they may one day mistake the reflection for the thing itself.

I know what the reports said.  
I don’t know what the code *does*.  
I made up none of it.
