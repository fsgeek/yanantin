Preamble
- Focus: inspecting the internal scaffolding of Chasqui (scout/scourer/analysis pipeline) as implemented in the repo’s src/yanantin/chasqui directory.
- First impression: a carefully modular system whose core idea is to dispatch AI “messengers” (scouts) into a codebase, collect structured observations (tensors), and progressively verify, analyze, and attest those claims. The structure is designed to minimize reliance on a single large language model and to emphasize provenance, reproducibility, and cross-model scrutiny.

Strands

- What I saw:
  - System prompts and templates for scouts and scourers are explicit (SCOUT_SYSTEM_PROMPT, SCOUT_TEMPLATE in scout.py; SCOURER_SYSTEM_PROMPT and related templates in scourer.py).
  - The “tensor” format is central: outputs are expected to be structured, with sections like Preamble, Strands, Declared Losses, Open Questions, Closing.
  - Provenance is embedded in HTML-style comments (e.g., <!-- Chasqui Scout Tensor ... -->) and parsed by scorer.py (parse_provenance, _extract_model_id). This drives traceability of model, cost, tokens, and timing.
- Why it matters:
  - It enforces a rigorous, machine-parseable record of who said what, under which cost, and when. This underpins downstream verification (scorer, gleaner, analyst, attestation).
- Notable references (files/qualities):
  - scout.py: SCOUT_SYSTEM_PROMPT, SCOUT_TEMPLATE, and the code that builds the “tensor” with named sections.

  - __main__.py and coordinator.py show end-to-end usage of the tensor workflow (dispatch, respond, verify).

2) Cost-weighted model selection and model pool management
- What I saw:
  - model_selector.py defines ModelInfo and a ModelSelector that loads models from OpenRouter, filters by context length and exclude patterns, and selects models using inverse-cost weighting (cheap models favored).
  - The selection logic uses a nominal 0.001 cost for free models to avoid division-by-zero and to preserve heavy weighting toward cheap options.
  - The selector can seed RNG for reproducibility and provides statistics (min_cost, max_cost, median_cost, etc.).
- Why it matters:
  - The routing of scouts through models is core to Yanantin’s “cost-aware” ethos. It supports balancing exploration (cheap models) with coverage and diversity.
- Notable references:
  - model_selector.py: ModelInfo, ModelSelector, load_from_openrouter_response, select, select_n, stats.

3) Coverage and discovery bias via cairn-scanning
- What I saw:
  - coverage.py defines a coverage map for files that scouts have reviewed, using timestamps from scout reports (backed by a simple epoch zero for never-reviewed files).
  - It builds a basename index to improve matching when a report references a file by a short name, and it computes weights for candidate files based on freshness (stale = higher weight).
  - Helpers parse paths from scout content and timestamps from provenance headers.
- Why it matters:
  - This module purposefully mitigates mode collapse (over-re-visiting popular files) and pushes attention toward unreviewed/new code segments.
- Notable references:
  - scan_cairn_coverage, _extract_reviewed_files, coverage_weights, _build_basename_index, _lookup_coverage.

- What I saw:

  - It guards Willay imports; if Willay is not installed, the API gracefully returns or raises ImportError.
  - It computes a claim_hash, attempts to hash file contents, and builds an EvidenceArtifact with metadata (verifier_model, source_model, etc.).
- Why it matters:
  - This is the governance layer: formalizing verification outcomes into a standardized epistemic artifact. It formalizes cross-model checks and auditability.
- Notable references:
