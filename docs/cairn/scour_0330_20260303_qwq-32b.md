### Strands  

#### **1. Cost-aware Model Selection**  
- **Where**: `model_selector.py` and `coordinator.py`  
- **Observation**: Models are selected *inversely by cost* via `ModelSelector.select()`, favoring cheaper models (e.g., a $0.0001/M token model is 100x more likely than $0.01/M). This creates a **cost-benefit feedback loop**: models that produce high-quality insights at low cost are prioritized, while expensive models with poor scores drift to the margins.  
- **Connection to Yanantin**: Implements the project’s principle of "complementary duality" — balancing human (costly) and AI (variable-cost) labor.  
- **Assumption**: The `ModelSelector` assumes OpenRouter’s pricing data is accurate and static. If costs fluctuate, decisions may misalign.  

#### **2. Structural Validation via Regex**  
- **Where**: `scorer.py`, `gleaner.py`, and `analyst.py`  
- **Observation**: `scorer.parse_provenance()` and `gleaner._PATH_PATTERN` rely heavily on regex to extract metadata and file paths. This creates a **single point of failure**: malformed scout outputs (e.g., missing `<!-- Chasqui ... -->` headers) will crash analysis.  
- **Risk**: Overly strict regex patterns could exclude valid paths (e.g., non-backtick-wrapped filenames). The `gleaner._BARE_PATH_PATTERN` mitigates this but may still miss edge cases.  

#### **3. Epistemic Loss Tracking**  
- **Where**: `analyst.py` and `attestation.py`  
- **Observation**: `analyst.ModelProfile` explicitly tracks "declared losses" like hallucinations or garbage claims, but `attestation._common_declared_losses()` embeds static losses (e.g., "Hallucination risk in verifier"). This creates an **assurance layer** but may underweight dynamic risks (e.g., a new model’s bias).  
- **Missing**: No mechanism to retroactively update old reports with new loss categories.  

#### **4. Coverage-Driven Exploration**  
- **Where**: `coverage.py` and `coordinator.py`  
- **Observation**: The `coverage_weights()` function prioritizes files based on **time since last review**, using a `basename_index` fallback. This ensures stale or newly introduced files (e.g., `evolve.py` in multiple directories) get attention.  
- **Flaw**: Basename matching could confuse files with identical names but different purposes (e.g., `utils.py` in two unrelated modules).  

#### **5. Prompt Engineering as Quality Control**  
- **Where**: `scout.py`, `scourer.py`, and `coordinator.py`  
- **Observation**: Scout prompts explicitly instruct models to *"declare losses"* and *"say what you made up"*. This **structured output pattern** (e.g., `### Strands` sections) is enforced via regex in `scorer.CONTENTAnalysis`. Breaking the format disqualifies the report.  
- **Strength**: Reduces noise. **Weakness**: Overly rigid for exploratory outputs, potentially stifling creativity.  

#### **6. Verification as a Second-Order Effect**  
- **Where**: `coordinator.py` and `attestation.py`  
- **Observation**: The system verifies claims by re-scouting them (via `dispatch_verify()`), but `MAX_VERIFY_PER_CLAIM=3` caps this to avoid infinite loops. However, `attestation.record_verification()` only stores the last verdict, losing historical context (e.g., earlier "CONFIRMED" vs. later "DENIED").
