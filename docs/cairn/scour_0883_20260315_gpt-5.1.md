### Strand 6 — Late Binding, Dead Weight, and Context as OS (T₂₈–T₂₉)

**T₂₈ — The Dead Weight**

Preserves:

- A generalized **late-binding hypothesis**:
  - Seen independently in: activity anchors, Jabberwock, mome, and now context compaction: write minimal facts now; materialize rich views later when asked, with unknown future ontology.
- Measurement (Phase 1):
  - 813 sessions, 668MB, 27,612 tool calls.
  - 79.4% of content is tool output — matches prior 78.2% from research program.
  - Amplification:
    - Unsegmented median ~13.6x.
    - Main sessions: 84.4x (each byte reprocessed ~84 times).
  - Simpson’s paradox: many short subagents hide the real amplification for main sessions.
  - Temporal survival: early outputs live longer; FIFO compaction is accidentally near-optimal.

The “dead weight” is all the tool output that stays in context after being consumed. KV cache makes it cheap to reread; but it still occupies scarce context.

Context compaction as currently practiced faithfully summarizes garbage.

**T₂₉ — The Fastest Read Is the One You Never Do**

Now we get:

- Phase 2 eval instrument:
  - Tools to compare FRESH vs COMPACTED conditions across 9 probes (documented failure patterns).
  - Result: compaction *hurts*:
    - Fresh: 0.49
    - Compacted: 0.36
- System prompt ablation:
  - Full prompt (40K) vs CLAUDE.md + MEMORY.md only (24K): same performance.
  - Removing identity section and hooks/safety *improves* project-knowledge score (0.72).
  - Ultra-minimal prompt collapses (~0.22).
  - ~40% of system prompt is dead weight for these tasks; some parts are actively harmful.

Tony’s OS metaphor:

- Context window = RAM.
- System prompt = pinned working set.
- Tool output = pageable.
- Compaction = GC (wrong tool; should be admission control).
- Proposal: treat system prompt sections and tool outputs as *pageable objects* with lifetimes, not fixed monolith.

Proxy-as-memory-manager:

- The Phase 1 proxy already sits in front of the model.
- It could strip known-dead sections, compress tool outputs to observations (e.g., graph edges), and manage a working set instead of a flat log.

Cross-project convergence with Episode:

- Episode independently finds repeated file reads and tool output bloat.
- Both sides agree: problem is not “insufficient compression” but *wrong representation*.

Losses: structured “Vorpal instead of summary” condition not tested; proxy rewrite not implemented; behavior probes (e.g., safety rules) not evaluated; Sonnet/Opus not tested; full-context baseline omitted for cost.

Future instances:

- The conclusion is strong: compaction of raw text history—as done now—does not preserve critical knowledge and often *dilutes* it.
- A different abstraction is needed: a tensor-like, typed working set, with OS-style pagination and late binding of details.
