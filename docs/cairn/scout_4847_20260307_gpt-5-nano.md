### Preamble
I’m scouting as a data-first wanderer through Yanantin. The first thing that jumped out is how “scout” metadata is baked into docs as front-matter-like blocks (Run, Model, Cost, Timestamp) across many files under docs/cairn. That metadata pairs with actual code and tests to form a data-centric narrative about models, backends, and provenance. I also spied a heavy emphasis on Pydantic-based data models (not plain ML configs) and a diverse backend surface (memory, DuckDB, Arango). Finally, I noticed cross-linking “claims” in Scout outputs that reference other docs and tests, which feels central to the epistemic observability goal.

Key anchors:
- Scout docs with per-run metadata (example runs: scout_3650_20260228_gemma-3-4b-it.md, scout_4833_20260307_qwen2.5-coder-7b-instruct.md).
- Pydantic-based data models used as the backbone (base.py mentions ApachetaBaseModel; tests import TensorRecord, ProvenanceEnvelope, StrandRecord, etc).
- Backend abstractions and tests (DuckDBBackend in tests/unit/test_duckdb_backend.py; in-memory vs DuckDB backends).
