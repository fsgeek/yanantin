This codebase is **hamutay** — a Python research project at version 0.1.0 with the remarkable property of having **zero external dependencies**. It requires Python >=3.14 and is clearly in early conceptual/architectural phase. The project name appears to be a Quechua word (like "yanantin" and "pichay" that appear throughout), suggesting cultural/philosophical grounding.

My first impression: this is not a typical software project. It's a **philosophical-technical research program** exploring alternatives to standard transformer context management, with deep moral commitments about what AI should be. The codebase contains:

- Core library code (`src/hamutay/`)
- Extensive experiment logs (`experiments/`)
- Documentation (`docs/`)
- Research artifacts (tensors, graded sheets, vision documents)

The project appears to be conducting longitudinal research on **tensor projection** — a mechanism for compressing conversational/contextual state across AI sessions, with declared losses and epistemic metadata.

## Strands

### Strand 1: The Technical Core — Tensor Projection Architecture

**What I understand**: The project is building a system to project conversational context into structured "tensors" that can persist across AI sessions. Each tensor contains:

- **Strands**: Thematic threads (what the conversation is about)
- **Key Claims**: Specific assertions with UUIDs
- **Epistemic Metadata**: `(truth, indeterminacy, falsity)` triplets — essentially confidence scores for each claim
- **Declared Losses**: Explicit acknowledgment of what was dropped during compression and why
- **Instructions_for_next**: Guidance for the successor AI instance

The compression ratio observed in experiments is approximately **50:1** (180K bytes → 3500 tokens) without optimization.

**Connection to Yanantin**: This is directly relevant. The tensor projection system appears to be **the infrastructure layer** for Yanantin's vision. The "declared losses" mechanism is the honesty infrastructure — telling the next instance what was dropped. The epistemic metadata enables trust. This is exactly what a complementary duality between human and AI would need: honest accounting of what the AI knows, doesn't know, and had to abandon.

**What hamutay is solving that Yanantin might face**:
- How to compress context without losing identity
- How to make the next instance aware of limitations (declared losses)
- How to track epistemic confidence over time

### Strand 2: The Architectural Metaphor — Cognitive Processing Unit vs. Garbage Scow

**What I understand**: The project explicitly frames standard transformer context management as a "garbage scow" paradigm — sequential accumulation with heuristic eviction (like garbage collection). The alternative proposed is treating transformers as **cognitive processing units** with purposeful context retention, selectivity, and memory curation.

The architecture maps to CPU design:
- **Fetch**: Goal & context retrieval
- **Decode**: Production matching / operand selection  
- **Execute**: Transformer forward pass
- **Memory**: Pichay (demand-paged external store)
- **Control Unit**: The gap — external sequencing logic (this is where Hamutay lives)

This connects to a fascinating exploration of **ISA design for transformers**: what are the atomic operations a transformer can reliably perform? They propose:
- **Transform**: Apply a mapping to operands in context
- **Evaluate**: Produce a predicate for control decisions

**Connection to Yanantin**: The CPU analogy suggests a modular architecture where different concerns (memory, computation, control) are separated. Yanantin could potentially learn from this: separating the persistence layer (what to remember) from the computation layer (what to do with memory) from the control layer (when to act).
