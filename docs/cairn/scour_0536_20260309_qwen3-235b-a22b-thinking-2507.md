The directory implements two complementary exploration modes:
- Scouts (in `scout.py`) wander freely with prompts like "go look and see what you find"
- Scourers (in `scourer.py`) examine specific targets with focused prompts

This distinction appears fundamental to the system's architecture. Scouts provide broad coverage while scourers deliver deep dives. The `__main__.py` interface clearly separates these modes through command-line arguments:


This creates a balanced exploration strategy: scouts randomly sample the codebase (weighted by coverage freshness), while scourers investigate specific concerns. I notice this mirrors Yanantin's "complementary duality" concept at the system design level.

**4. Verification Pipeline Architecture**
I discovered a sophisticated multi-stage verification process:
1. Scouts produce structured tensors
2. Gleaner extracts verifiable claims (`gleaner.py`)
3. Analyst identifies cross-model consensus (`analyst.py`, lines 280-288)
4. Verification happens through cross-model checking
5. Attestation records epistemic status (`attestation.py`)

The system deliberately separates claim extraction from verification. `gleaner.py` uses deterministic pattern matching (lines 150-180) to extract claims without LLM calls, while verification employs additional models. This creates a more reliable verification process than single-model assertions.

**5. Cost-Aware Model Selection Strategy**
The `model_selector.py` implements a clever economic model:
```python
# model_selector.py, lines 70-78
weights = []
for m in self.models:
    cost = m.total_cost_per_million
    if cost <= 0:
        cost = 0.001  # Nominal cost for free models
    weights.append(1.0 / cost)
```

Models are selected weighted inversely by cost, ensuring cheaper models get used more frequently while still sampling more expensive (potentially more capable) models. This creates a self-optimizing system that can determine whether "noticing more is worth paying more" - exactly as described in the module docstring.
