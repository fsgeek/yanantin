### Preamble  
`hamutay` is a research‑grade prototype for a **structured memory / cognition architecture** that treats each transformer inference as a *tensor* – a JSON‑serialisable state that contains:

* **Strands** (thematic threads)  
* **Claims** (factual statements with neutral‑logic epistemic scores)  
* **Declared Losses** (explicit notes on what was omitted or dropped)  
* **Instructions for Next** (branch‑prediction or hand‑off direction)

The project is heavily experimental: it runs a large suite of *experiments* (`experiments/…`) and logs (`logs/…`), records *tensor cycles* (`tensor_cycle_XXX.json`) per turn, and maintains a *pipeline* of stages (`prepare → invoke → integrate → handoff`).  

The code is split into logical modules:  
* **core** – models, pipeline, policy, utilities  
* **memory** – blocks, message store, pager (persistent message store)  
* **projection** – packing, idle detection, regions (layout)  
* **gateway** – launcher & orchestration of experiments  
* **analysis / eval** – scripts for post‑processing of tensors and experiments  

The “idle” module (`src/hamutay/projection/idle.py`) implements a simple **idle‑cache‑TTL** logic: after ~5 min of inactivity the Anthropic KV cache is presumed expired, so a new “restructure” can be sent at no extra write cost.  

Overall, the project is a *living laboratory* for exploring how to let a stateless LLM maintain continuity across turns, across sessions, and across *future* instances, a theme that sits squarely on Yanantin’s agenda.

### Closing

`hamutay` demonstrates a **comprehensive, experimentally‑validated approach** to building a *distributed, self‑aware* memory system for stateless LLMs. Its key strengths that Yanantin can borrow are:

* **Explicit loss tracking** – the tensor explicitly records what was omitted, turning hidden state loss into a visible, queryable artifact.  
* **Lamport‑style logical time** – the cycle counter is a robust causal clock that decouples state progression from physical time.  
* **Idle‑aware cache handling** – the simple `IdleState` logic shows how to detect when a cache is likely stale and trigger a free restructuring.  
* **Structured, forward‑looking instructions** – embedding `instructions_for_next` keeps future instances aligned without re‑processing the entire conversation.  
* **Pipeline abstraction** – clean separation of stages (`prepare`, `invoke`, `integrate`, `handoff`) mirrors Yanantin’s own stages and clarifies responsibility boundaries.  
* **Data‑driven experimentation** – the experiments provide a template for systematic evaluation and iteration, vital for refining the architecture.

The biggest gaps are in the **fault‑in retrieval** and the **exact mechanics of idle‑based restructuring**. If Yanantin can implement a lightweight, deterministic “page‑fault” system that pulls missing content from long‑term logs, and can emulate the `IdleState` logic to trigger re‑projection when the cache is stale, it would inherit most of `hamutay`’s proven robustness.  

For the Yanantin team: consider adopting the *explicit loss* and *Lamport clock* mechanisms, and build a *cache‑aware idle detection* layer. The experimental scaffold in `hamutay` (logs, metrics, tests) is a solid blueprint for your own research pipeline.
