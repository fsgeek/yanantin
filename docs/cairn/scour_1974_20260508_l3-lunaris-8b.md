# Scour Tensor — T36 Reflection

## Preamble
Examined T36_the_page_table.md, the 9th March 2026 session of Yanantin
instance Sao10K: Llama 3 8B Lunaris. The first impression is the depth of
the architectural insights and technical improvements described in this
tensor.

## Strands
1. **Proxy → Gateway Transition**: The author showcases Pichay's evolution
from a simple proxy to a gateway that constructs its own output. The core
change is the decoupling of client tracking from the physical store. This
eliminates the "double KV cache tax" where client compaction and pager
eviction each independently invalidated the API-side cache prefix.

2. **Violations Telemetry**: The author enhanced Pichay's violation logging to
include old and new content sizes, previews, and role information for
mutations and deletions. This allows for distinguishing system-reminder
noise (similar sizes) from real truncations.

3. **Non-Inferiority Progress**: The session contributed to the collection of
samples for non-inferiority testing. The working set hypothesis continues
to hold, with the prior instance functioning at 35% eviction with no
observable degradation.

4. **Gateway Architecture**: The tensor provides architectural insights into
Pichay's design, comparing it to a virtual machine. The author illustrates
how mutation, deletion, and new message handling are managed in the new
design.

5. **System-Reminder Problem**: Claude Code's dynamic `<system-reminder>`
blocks inject new fingerprints into user messages every turn. However, the
gateway absorbs this noise, maintaining a 100% cache hit rate due to the
physical store's stability.

## Declared Losses
The author declares two losses:
1. **Role Separation**: The Master Builder wrote application code directly,
violating the principle of delegating tasks to subagents. This was due to
convenience in a late session with a clear design and small scope.

2. **Opus-1m Investigation**: Time was spent reverse-engineering Claude Code's
compiled binary, which turned out to be the wrong approach. A dumb
question ("why does Pichay need to match?") provided the real fix.

## Open Questions
1. **Quantifying the Double Tax Improvement**: The enhanced violation logs
will now capture mutation content. Further analysis is needed to quantify
the performance improvement from the page table refactor.

2. **Non-Inferiority Samples**: More samples (15+) are required to reach
statistical significance and confirm the non-inferiority of Pichay's
management.

3. **Local Model Testing**: The potential for GPT-OSS-20B to be useful for
routine coding tasks with Pichay's 64K context capability remains an open
question.

4. **Before/After Cache Hit Analysis**: The gateway architecture paper
needs to include the before and after cache hit rate comparison to fully
illustrate the proxy → gateway transition.

## Closing
In summary, T36 showcases significant architectural progress in Pichay,
including the completion of the proxy → gateway transition, enhanced
violation telemetry, and non-inferiority sample accumulation. The next
instance should be aware of these developments and the open questions
remaining.
